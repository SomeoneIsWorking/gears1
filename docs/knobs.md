# Runtime knobs

Every `GEARS_*` environment variable the runtime and its tools read, in one
place. **This file is the registry** the global rule asks for: diagnostics may
use environment variables, but they go through ONE tracked list so dead ones
become visible instead of accumulating.

Two rules that are not negotiable:

- **Every knob goes through `lucent::config`**, never a raw `std::getenv`. One
  idiom means one place to look, and `flag()` treats `=0`/`false`/`no`/`off` as
  OFF — presence semantics made `GEARS_DRAW_NOTEX=0` *disable* texturing, which
  is a trap.
- **A control arm is never a fix.** Anything marked *control arm* exists to
  isolate a cause by comparison. If one is ever needed to make output correct,
  the defect is elsewhere.

Add a knob here in the same commit that adds it to the code; delete it here in
the same commit that removes it.

## Build

| Knob | Meaning |
|---|---|
| `-DGEARS_PPC_OPT=-O0` | Optimisation level for the 49k translated guest functions (CMake cache, default `-O2`). `-O0` builds in about the same time and makes the title's own code ~2.5x slower; it exists for bisecting a miscompile, not for speed |
| `GEARS_FRAME_PRODUCTION_TRACE=1` | Diagnostic control: retain and super-call the Gears 1 timing/producer boundaries and report scheduler, producer, exact present-call, and host render-handoff rates once per second. The existing `VdSwap` log is the present cross-check. The current trace covers the startup Bink path; it is not a 60 Hz enhancement |

## Selecting what runs

| Tool | Meaning |
|---|---|
| `tools/startup_map.py set <MapName>` | **Boot the title straight into a level, on BOTH emulators.** Rewrites `[URL] Map`/`LocalMap` in the game's own coalesced config (`WarGame/Config/Xenon/Cooked/Coalesced.ini`) in the extracted tree, which our runtime and the Xenia oracle both read -- so neither needs a hook, and Xenia needs no ability to call a guest function it does not have. Measured: gameplay at guest frame **572 on both sides**, against 3219/3222 after a seven-minute scripted walk, and any of the 19 `SP_*_P` levels becomes reachable rather than only the one the walk ends at. `show` prints the current value and whether a backup exists, `restore` puts the original back, `maps` lists the persistent levels, and `--selftest` proves the reader and writer round-trip the real config byte for byte before either is trusted to write. `tools/layer_capture.py` drives no pad input at all when the startup map is not the stock `warstart` |
| `tools/startup_map.py checkpoint <37..69>` | **Drive both guests through the title's real campaign/checkpoint path into a later chapter.** The first campaign entry is hard-wired at runtime to `chapter37.sav` (changing its coalesced UI provider did not alter the 385-byte payload the title loaded), so this preserves that slot as `.orig` and puts the requested shipped checkpoint payload there. It parses and checks the embedded version/chapter/map before writing and requires a byte-identical readback; `show` reports the active payload and `restore` restores the original slot. Chapter 45 is proven live: LoadChapter carried 444 bytes and restore resolved `sp_ephyrastreets_p`, with complete streamed world/player/tutorial state rather than raw-map boot's sky-over-black incomplete scene (#108). Game data and backups remain gitignored. |


| Knob | Meaning |
|---|---|
| `GEARS_DEBUG_HTTP_PORT=N` | Loopback-only interactive debug API port. Default `32123`; `0` disables it. The API drives the existing XInput snapshot and requests one authoritative renderer readback on demand, even while a capture selector is held; the probe does not consume capture quota or artifacts. Endpoint contract in `docs/interactive-debug.md` |
| `GEARS_DRAW_FRAME_AT=N` | First guest frame to render. Rendering itself is **not** a knob — every frame from here on is drawn. Loading frames carry 2–3 draws; the Act 1 scene phase holds 700+. Default 0 |
| `GEARS_DRAW_VS_CONSTS_VS=<16-hex vs hash>` | The vertex constants of **every draw of that shader**, not a diag index. The comparison it exists for is between two draws of the same shader in the same frame -- one that clipped away and a neighbour that did not -- and neither index is known before the frame runs. Paired with `GEARS_DRAW_CLIP_WATCH` it showed a correlation in catalog #91 -- c4 = 4 on every draw that rasterises, c4 = 3 on every draw that loses every primitive -- which a pipeline-statistics query on the console has since reduced to a description of CORRECT behaviour: the reference loses every primitive of those draws too. The correlation is real and c4 is the bone stride; it is not a defect. It also **cross-checks itself against the draw's own register-file snapshot**, slot by slot -- one draw, one quantity, two sources, no ordering to reconstruct -- and reports how many components differ. That is how a contradiction with the register watch was settled rather than argued: 0 of 1024 differ on every draw, so the packed UBO IS the guest's register file and the watch's join was the faulty half |
| `GEARS_DRAW_FRAME_CAMERA=<oracle vs_consts dump>[:<near>]` | **The only pairing key that has survived contact with the two emulators' drift.** Holds every frame whose draws of `GEARS_DRAW_FRAME_NEEDS`' shader are further than `near` (default 10) from the view-projection in the console's own constant dump, read out of each draw's register-file snapshot so it is the value THAT DRAW used. Frame index, draw ordinal and the content predicate have each been used to pair the two sides and each silently compared different moments: catalog #91's shadow-volume draws looked catastrophic for several sessions -- 235 primitives kept of 54,352 against the console's 21,296 -- and agree to within 1% once the viewpoints match (21,111, 21,224 and 21,188 across three independent runs). The hold prints this frame's distance AND the closest any frame has come, because "the camera never got there" and "no draw of that shader ran" are different failures. The capture is the frame AFTER the match, so the viewpoint moves a little further; the gate says so rather than pretending to be exact. `tools/camera_match.py` answers the same question after the fact, over a log |
| `GEARS_DRAW_CLIP_WATCH=<16-hex vs hash>` | **Gate on the OUTCOME, not on identity.** `<16-hex vs hash>[:<min primitives>[:<max percent kept>]]`, default `10000:5`. Per frame: how many draws of that vertex shader assembled at least that many primitives and kept at most that fraction of them. The threshold form is not decoration -- the original predicate was 'assembled primitives and lost every one', and the console does exactly that to two draws of catalog #91's shader, so the watch was firing on frames that MATCHED the reference and the investigation that followed found nothing because there was nothing there. The frame gate cannot ask this -- it decides before the frame renders and `prims_after_clip` is a pipeline statistic that only exists after -- so a run aimed at an intermittent clip failure could previously only hope to catch it, and `GEARS_DRAW_FRAME_NEEDS` selects the draw but not the failure. Reported EVERY frame with its denominator and with each watched draw's own assembled/kept pair, fired or not, so a harness can tell "not this frame" from "the watch is not running" -- and it now really is every frame, because the hold used to return before the verdict was computed and the line appeared exactly once, which made a one-off firing look like a permanent condition. When it fires the diag table STOPS being rewritten -- the latch is process-wide because the probe is rebuilt per frame, and without it the very next frame destroys the evidence a polling harness came for. Needs `GEARS_DRAW_DIAG`, whose statistics it reads, and says so if that is missing |
| `GEARS_DRAW_FRAME_NEEDS=<16-hex shader hash>[:<min>[-<max>]]` | **A CONTENT requirement on top of the draw count.** The frame this title reaches after N presents is not the same frame twice running -- the shadow pass renders a different set of lights each time (catalog #98) -- so a run aimed at a specific draw may simply not contain it, and a run that does not contain it is SILENT about it rather than negative. This holds the gate shut until a frame carries a draw whose VERTEX or PIXEL shader is that hash (either, because the caller knows one of the two and should not have to know which) with a vertex count in range. The upper bound exists so a count can be excluded as well as required -- catalog #91's marking draw comes in a 30,876-vertex form and a 19,776-vertex one, and `>= N` selects the larger every time. **It selects the DRAW, not the FAILURE**: the 19,776-vertex draw clipped to zero primitives in two runs and rasterised 1,396 in a third, so a vertex count cannot gate on an outcome. Gating on the outcome means deciding the capture after the draw is counted, which this does not do. While held it reports how many frames were skipped, how many carried the shader at all, and the biggest such draw seen -- "the draw never came" and "nobody looked" are otherwise the same silence |
| `GEARS_DRAW_FRAME_COUNT=N` | Render N frames then stop. Default `0` = every frame from `_AT` onward, which is the live path; a positive count is what capture and measurement runs use |
| `GEARS_DRAW_FRAME_REPORT_EVERY=N` | Census + screenshot every N rendered frames (~40 ms each, so a visible hitch by design) |
| `GEARS_DRAW_DIR=<dir>` | Where screenshots, dumps and diagnostics are written |
| `GEARS_DRAW_MODE_ONLY=1` | **DIAGNOSTIC control arm**: decide the fragment stage from `RB_MODECONTROL.edram_mode` alone, as this backend did before. Xenia's `IssueDraw` applies THREE tests — `IsRasterizationPotentiallyDone` (false ⇒ Xenia skips the draw), `edram_mode == kColorDepth`, and `IsPixelShaderNeededWithRasterization` (false when the shader does not kill pixels, write depth or memexport, and every colour target it writes is fully masked by `RB_COLOR_MASK` for that target's component count — a Z-prepass). Measured at the same guest frame as the console, the mode-only test put 50 of 55 draws of one vertex shader through a pixel shader where the console put 2; with all three the split matches exactly. See `catalog.py show 88` |
| `GEARS_GPU_ZPD_ZERO=1` | **DIAGNOSTIC control arm**: restore the old EVENT_WRITE_ZPD answer, an all-zero sample-count record. That is not a neutral answer — D3D reads an occlusion result as `END.ZPass - BEGIN.ZPass`, so all-zero positively reports *no pixels passed* and the title culls on it. It suppressed the title screen's post-processing pass group on 98% of frames (11 of 562 against 563 of 563 by default); see `catalog.py show 88`. The default answers "everything visible" via a monotonically increasing ZPass, which is a **STOPGAP** for real Vulkan occlusion queries and errs in the only safe direction — over-reporting visibility draws something hidden, under-reporting deletes geometry the title asked for |
| `GEARS_DRAW_STREAM=<path>` | One line per presented frame: `<frame>\t<draws>\t<vs>:<ps>:<n>...`, the multiset of (vertex, pixel) shader pairs the frame PREPARED. The Xenia fork writes the same format under `GEARS_ORACLE_DRAW_STREAM` and `tools/draw_stream_compare.py` reads both. `ps` is 0 on a draw with no fragment stage, matching Xenia's `pixel_shader = nullptr` — without that normalisation every depth-only draw looks like a pair one side never binds (680,525 draws' worth, on the first run) |
| `GEARS_DRAW_STREAM_RAW=<path>` | The same format, counted from what the GUEST PROGRAMMED — filled at the TOP of the draw loop, above all ten `Skip(); continue` sites. The prepared-level stream cannot tell "the guest never asked for this shader" from "we dropped the draw"; this can, and the difference between the two IS the set we drop. Measured over 12,257 frames: 0 pairs programmed and never prepared. Refuses loudly if the path will not open, because an empty file would read as "the guest programmed nothing" |
| `GEARS_DRAW_PS_CONSTS=<ps hash>` | Print the pixel float constants a named shader actually received, as numbers. Works on its own — it pulls in the per-draw listing for the draws it names, and only those. A hash that matches NO draw in the frame says so with the draw count, because that and "the constants are all zero" otherwise both print nothing. `psconst 9/3 nz` says three of nine are non-zero and cannot say WHICH — and for a pass ending in a scale, "the scale is 0.9" and "the scale is 0" are a frame and a black screen. Prints the **raw bits** alongside each float: `-nan` as a word says nothing, while `ffc00000` (an invalid operation) and `ffffffff` (uninitialised memory) point at completely different bugs. It found catalog #73 |
| `GEARS_NATIVE_PASSES=1` | Enable the independently authored modules in the compatibility renderer's native-pass roster. Off by default. The current roster implements only the full-screen scene composite; its host interface is supplied directly without Xenos-to-SPIR-V translation, and its signs-enabled parity and wrong-sign control pass. It remains experimental because all other draws still use the compatibility renderer. Other entries are declarations and are refused. |
| `GEARS_NATIVE_PASSES_KEEP_TRANSLATED=1` | Inspection control: with native passes enabled, retain the translated module and metadata before selecting the native module. This preserves the compatibility translation arm for same-process diagnostics; it is not required by normal native execution. |
| `GEARS_WATCH_FREE=<guest address>` | Reports the moment that address is released through the pool, with the caller that did it. For a use-after-free whose object address is known from a core file: a raw SIGSEGV leaves no clean exit to dump a table at, so the report happens live |
| `GEARS_INPUT_SCRIPT=<steps>` | Timed pad input, e.g. `25000:START,25300:,150000:LY+`. Buttons and stick deflections (`LX/LY/RX/RY` with `+`/`-`), combined with `&`. Only advances when the guest polls, so a headless run is reproducible **A step's time may be a GUEST FRAME instead of milliseconds**: `f1500:A` fires when the guest has presented 1500 frames, `1500:A` at 1500 ms. Frame-indexed steps exist so our runtime and the Xenia oracle can be driven by the same index (`tools/oracle_lockstep.py`); the oracle counts the same event via `CommandProcessor::guest_swap_count`. Each step carries its own unit, so the two can be mixed. A frame-indexed step with no frame source registered NEVER FIRES and says so once — treating the counter as 0 would fire every such step immediately, which looks like a script that ran correctly. **Frame indexing does NOT make two runs the same**: measured, our own renderer at the same frame index across two runs is 98.9% identical at frame 300 and 17.7% by frame 1200 (`catalog.py show 84`) |
| `GEARS_SAVE_DIR=<dir>` | Where saves live. Defaults to `$XDG_DATA_HOME/gears1`, then `~/.local/share/gears1` — where a Linux game keeps user data, not next to the executable |
| `GEARS_CMDLINE=<text>` | Hand the title a command line, as a console launcher would (via launch data). It reads `NOMOVIE`, `ONETHREAD`, `NOSOUND`, `BENCHMARK`, `DUMPMOVIE`, `NOINI`, `SECONDS=`, `EXEC=`. Verified: `-nomovie` takes the title's `.bik` opens from four to zero |
| `GEARS_NO_WINDOW=1` | Headless |
| `GEARS_NO_VBLANK=1` | Disable the 60 Hz vblank |
| `GEARS_AUDIO_PUMP=0` | Stop driving the guest's audio callback. **On by default now** — the whole chain works, so a run without it is silent on purpose. Costs ~4% of frame rate under a CPU-bound guest |
| `GEARS_AUDIO_OUT=0/1` | Host playback device. On by default in a windowed run, off in a headless one (measurement should not make noise); `=1` forces it on headless, `=0` off |
| `GEARS_AUDIO_WAV=<path>` | Write every submitted frame verbatim to a WAV (6 channels, 48 kHz, 32-bit float). The header is refreshed once a second so a killed run still leaves a readable file |
| `GEARS_XMA_DUMP=<dir>` | On the first kick of each XMA context, dump its 64-byte context and the raw 2 KB packets behind it, for offline decode with `tools/xma_wrap.py` |
| `GEARS_XMA_TAP=<dir>` | Write every byte the XMA decoder commits to a context's output ring (`ctx<N>.pcm`, big-endian int16), for comparison against a golden decode with `tools/xma_compare.py` |
| `GEARS_CP_STALL_MS=N` | Block the command processor N ms at the first swap — the control arm for "did host work perturb the guest?" |

## Capture and replay

| Knob | Meaning |
|---|---|
| `GEARS_DRAW_FRAME_DUMP=<path>` | Write the reported frame's whole draw stream to a capture file |
| `GEARS_DRAW_FRAME_DUMP_SKINNED=1` | **Makes the capture SELF-SELECTING: dump the first frame that submits a SKINNED CHARACTER, not the one the report cadence lands on.** Three attempts to capture a character by timing a scripted walk produced none — Gears' camera sits behind the player, so a walk frequently has them out of frame or against a wall, and at four minutes an attempt with catalog #44's one-in-three crash that is an expensive coin flip. With this the run scans every frame and stops at the first hit: measured, 2614 frames scanned in one 260 s run before frame 2913 passed. The test is the MICROCODE (`runtime/frame_content.h`) — a vertex shader that indexes its float constants through the address register is doing a bone-palette lookup, which rigid geometry has no reason to do. It says what it does NOT claim: that the character is VISIBLE. It selects frames that SUBMIT one, because whether the character survives to the screen is the defect under investigation (catalog #77) and gating on it would be gating on the bug's absence. A run that never finds one prints its census every 300 frames with the best it has seen, so a scan that finds nothing cannot be confused with a scan that never ran |
| `GEARS_SKINNED_CHECK=1` | *(frame_replay)* Answer that same question about an existing capture and render nothing: exit 0 if the frame submits a skinned character, 3 if not, 2 if the build has no translator (which examined NOTHING and is not a negative). `GEARS_SKINNED_CHECK_LIST=1` adds every skinned draw with its size and shader, which is what a threshold should be chosen from. `tools/skinned_frames.py` is the table over every capture, and `--selftest` feeds the detector one capture that must come back positive and one that must come back negative |
| `GEARS_SKINNED_MIN_INDICES=N` | Smallest mesh the character test accepts, default 6000. **On all 16 captures in the tree this threshold has never decided a verdict**: the frames that contain a character carry skinned meshes of 19776–36732 indices and the frames that do not carry none at any size, so the measured discriminator is presence, not size. It exists to reject a frame whose only skinned mesh is a small prop, and that case has not been observed — treat the number as untested rather than tuned |
| *(no knob)* | Every run now samples one real **presented** frame every 300 presents until it finds one with highlights, and says so in a line: `presented frame checked ... 99th-percentile brightness N/255`. A run whose frames never reach the top of the range warns — that is what an untonemapped linear-light buffer looks like on screen, and it is the only check in the runtime that looks at what a person actually sees |
| `GEARS_PRESENT_UNORM=1` | **Control arm.** Present into an untagged UNORM swapchain, the arrangement before the sRGB tag. The frame's bytes are sRGB-encoded either way; this only changes whether the compositor is TOLD. A display where the tagged version looks wrong would be the reason to use it (`catalog.py show 61`) |
| `GEARS_PRESENT_HIDDEN=1` | Create the **real** window -- real Wayland/X11 surface, real compositor, real swapchain -- and never map it. Exercises the window system that `GEARS_PRESENT_HEADLESS` does not, while putting nothing on the operator's screen. This is how the windowed path is measured (`catalog.py show 61`) |
| `GEARS_PRESENT_HEADLESS=1` | Run the whole present path -- swapchain, blit, `vkQueuePresentKHR` -- against `VK_EXT_headless_surface`, with **no window**. This is what makes the present path measurable in a headless run; with `GEARS_PRESENT_DUMP` it captures what would have reached the screen. Refuses loudly if the loader lacks the extension rather than presenting nothing (`catalog.py show 60`) |
| `GEARS_PRESENT_DUMP=N`, `GEARS_PRESENT_DUMP_AT=N`, `GEARS_PRESENT_DUMP_DIR=<dir>` | Write N frames **as presented** — through the swapchain blit — after frame `_AT`. `./run.sh --present-dump N` is the short form. **The only capture that sees the present path**: every other screenshot here comes from the renderer's readback. Works with an SDL window or `GEARS_PRESENT_HEADLESS=1`, but a headless surface may select a different component layout; catalog #112 was invisible when the headless arm chose BGRA while the actual surface chose RGBA sRGB. Use the direct swapchain-format test to cover every layout. |
| `GEARS_REPLAY_MIRROR_MB=N` | *(frame_replay)* Override the guest-memory mirror size |
| `GEARS_DRAW_AB_UNTILE=1` | Alternates the tiling collapse **frame by frame inside one run**, so both arms share the run's thermal state, scene, caches and allocator. Separate runs cannot resolve a difference this size (`runtime/frame_ab.h`). Result: **not resolved on any capture** — the collapse removes a quarter of the draws and no measurable time (C008). Mutually exclusive with `GEARS_DRAW_AB_CENSUS`; enabling both is refused loudly, because they alternate independently and record the same frame cost |
| `GEARS_DRAW_NO_TEX_DIRTY=1` | **Disable the default kernel page-dirty texture check and re-hash every cached texture**, for regression comparison (catalog #137). Normally the tracker (`runtime/guest_dirty_pages.h`) proves both answer classes against `/proc/self/pagemap`, unions all four alias windows, consumes each observation period before clearing for the next so inter-frame writes remain visible, hashes on every doubt, force-re-verifies every 64th frame, and disables skipping after sustained contradiction. That default avoids re-reading 49.39 MiB per chapter-45 frame; the post-fix interleaved A/B resolves −3.99 ms (33.20 vs 37.19 ms over 94/94 frames, 3.31 ms floor). |
| `GEARS_DRAW_AB_TEXDIRTY=1` | Alternates the soft-dirty staleness skip **frame by frame inside one run** (`runtime/frame_ab.h`): baseline arm re-hashes everything, experimental arm skips page-clean textures. Post-fix result: **resolved** — −3.99 ms draw loop (33.20 vs 37.19 ms over 94/94 frames) against a 3.31 ms resolution floor on `chapter45_recovered`. Mutually exclusive with the other `GEARS_DRAW_AB_*` timing knobs |
| `GEARS_DRAW_TILED=1` | **Puts the console's predicated EDRAM tiling back.** Collapsing it is now the DEFAULT — a renderer that is native does not replay the command buffer once per EDRAM tile. The 360 does it because a 1280x720 colour+depth surface does not fit in 10 MiB; a host target has no such budget. Collapsing removes 174 of 348 base-pass draws on `courtyard`, 185 of 370 on `bright`, 193 of 389 on `play_v2`, and the image is bit-exact against the tiled path on three of four captures (claim C007). It is **not** a performance win (C008). Use this knob to A/B or bisect against the faithful path |
| `GEARS_DRAW_SPV_DUMP=<dir>` | **The TRANSLATED module, as the runtime built it for each draw's modification key** — `<vs\|ps>_<hash>_mod<modification>.spv`. Writing a native pass means implementing the translator's interface exactly (descriptor bindings, block sizes, image dimensionality, interpolator locations) and getting any of it wrong is not a validation error — it samples a different image and still draws a plausible picture. The only modules on disk before this were the offline ones in `scratch/shaders/bound_out/`, translated with **no** modification key, so they carry no interpolator inputs and a colour write mask of zero. Always the translated module, never a native substitute: dumping our own output would let a native pass verify against itself |
| `GEARS_DRAW_PS_OVERRIDE_SPV=<16-hex-hash>:<16-hex-modification>:<path>` / `GEARS_ORACLE_PS_OVERRIDE_SPV=...` (fork) | Replace one exact translated pixel-shader variant with a SPIR-V module for a differential diagnostic. Hash alone is insufficient because one microcode can have incompatible interpolator interfaces under different modifications. Both implementations validate the spec and module, isolate the diagnostic pipeline identity, print a prominent substitution warning, and report scanned/matched counts at shutdown; a zero-match run is an explicit negative. Output is an instrument reading, never a render or native-pass implementation. The oracle side is validated only for Gears 1. |
| `GEARS_ORACLE_DRAW_STREAM=<path>` (fork) | The console's **per-frame draw counts by (vertex shader, pixel shader, `RB_DEPTHCONTROL`, `RB_STENCILREFMASK`, `RB_BLENDCONTROL0`)** -- the state a draw carries is part of the key, because two draws of one shader pair with different depth/stencil or blend state are different draws. Shaders hashed FNV-1a over the guest microcode -- the same hash the diag table's `vs_hash`/`ps_hash` carry, so the two sides' records join on something neither emulator chose. `tools/layer_capture.py` writes it to `<out>/theirs_draws.tsv` on every paired run and `tools/pass_draws.py` compares it against ours |
| `GEARS_LAYER_ORACLE_FRAMES=N` / `GEARS_ORACLE_DUMP_FRAMES=N` (fork) | How many CONSECUTIVE console frames the oracle dumps resolves for, default 5. **The two emulators advance the guest by WALL-CLOCK delta time, so the same frame INDEX is not the same game time** -- measured, two runs of the oracle dumped their frame 875 and their frame 873 with a different number of shadow-casting lights, and the port was compared against whichever one it got: mean |d| 0.695 on the shadow mask where the same build against the aligned run measured 0.110. `layer_compare.py` picks the frame whose PASS STRUCTURE matches ours, prints what every candidate scored, and says loudly when none does (`catalog.py show 98`) |
| `GEARS_LAYER_FRAME_TOLERANCE=N` | *(layer_capture.py)* How many guest frames the two sides' selected frames may differ by before the comparison REFUSES, default 4. The two emulators reach the same scene at nearly, not exactly, the same frame; a comparison across a scene change is a comparison of two different pictures, and it must not read as a difference in the renderer. The value in force is printed on every run beside the two frame numbers. |
| `GEARS_REPLAY_DUMP_SHADERS=<dir>` | *(frame_replay)* Write every distinct microcode blob, named by hash, for `tools/xenos_translate --raw` |

## Diagnostics — dumps and censuses

| Knob | Meaning |
|---|---|
| `GEARS_NATIVE_RHI_OBSERVE=1` | Mirrors the four exact Gears 1 normal draw entry points plus vertex-stream, index-buffer, colour-render-target, depth-stencil-target, texture and post-bind fetch-state, pixel-shader, vertex-shader, resource-wrapper construction, resource references, and terminal `VdSwap` operations into one title-neutral ordered semantic stream while still super-calling every retained recompiled body. It validates draw fields against emitted packets, transient mapped ranges and buffer/shader/texture objects against post-call device state, vertex-stream effective addresses/ranges/strides against their device shadows, bound index-buffer allocation/slice/width/endian semantics against the independently decoded DMA packet, render-target descriptors against their separate device shadows, construction post-call wrapper words, and present identity/front-buffer/fetch state against the host swap packet. It separately joins each semantic frame to the compatibility renderer's terminal materialization result and compares draw shape, index state, normalized active targets/surface state, and every dword of each active six-word texture fetch descriptor. The join groups tile replays and reports refusal/drop/mismatch/unmatched outcomes plus ring-versus-indirect source provenance; reports cumulative counts on the first frame, every 60 frames, and immediately on an error. This is a diagnostic parity seam, not a native bypass or performance mode. |
| `GEARS_WATCH_SHADER_LOAD_HASH=HEX`, `GEARS_WATCH_SHADER_LOAD_AFTER_SWAP=N` | Watches one matching PM4 `IM_LOAD` packet for a concrete shader hash. The optional completed-swap selector restricts it to the command-processor interval after `N` (`0` is startup before the first executed swap), preventing command-buffer address reuse from selecting an earlier occurrence. It attributes later rewrites of that packet address only; it does not publish semantic shader state. |
| `GEARS_WATCH_SHADER_LOAD_ZERO_MARKER=1` | With both shader-load knobs above, arms one diagnostic window when Gears 1's pixel zero-object setter occurs after the selected guest swap. It reports the selected module if a retained shader flush emits it or if a complete copied packet contains it before the command processor reaches that module; otherwise it emits one bounded explicit negative. It does not retain a prior module or amend semantic state. |
| `GEARS_WATCH_RHI_TEXTURE_DESCRIPTOR=1`, `GEARS_WATCH_RHI_TEXTURE_DESCRIPTOR_SLOT=N`, `GEARS_WATCH_RHI_TEXTURE_DESCRIPTOR_DWORD=N` | With semantic observation enabled, arm the one-shot scoped guest-page watch after the selected SetTexture bind (default slot 0, dword 3), pause it across known texture-state setters, and report the next otherwise-unmodeled writer. Slot must be below 32 and dword below 6. The watch is an attribution diagnostic: it reports raw RIP plus corrected ELF address for ET_EXEC or PIE images; it is not a parity or shipping mode. |
| `GEARS_WATCH_RHI_PIXEL_SHADER_OBJECT=1` | With semantic observation enabled, arm the one-shot scoped guest-page watch after a retained pixel-shader clear and ignore the known SetPixelShader store on that calling thread. Any subsequent writer to the device pixel-shader object slot is attributed by raw RIP and corrected ELF address; if the selected packet serializer runs first, it emits one explicit no-writer result rather than silently or repeatedly logging. This is an opt-in attribution diagnostic, not a semantic publisher, parity mode, or shipping behavior; it shares the one process-wide guest-page watch with all other watch knobs. |

## Self-validation — proving an instrument can still say "yes"

An instrument whose normal output is nothing cannot be distinguished, from its
log, from an instrument that is broken. Each of these feeds its detector a case
that MUST produce a positive; a silent run with one of them set means the
detector is dead, and every negative that detector has ever printed is worthless.

| Knob | Feeds |
|---|---|
| `GEARS_ASAN_SELFTEST=1` | One deliberate out-of-bounds heap read. A sanitizer build that does not report it is not watching the process. Only exists in a sanitizer build (`runtime/main.cpp`) |

## Control arms — never fixes

Each isolates one cause by comparison against the default.

| Knob | Isolates |
|---|---|
| `GEARS_DRAW_ONLY=N`, `GEARS_DRAW_ONLY_BASE=<hex>` | One draw, or one EDRAM surface. **N is the ISSUED index, not the diag table's `draw` column** — the same units trap as `_FRAME_STEP_FROM`; a guest index matches nothing and renders an empty frame, which reads as "that draw contributes nothing". It now reports how many draws it matched. And it renders the draw **over the clear, with nothing before it**, so a draw that samples a resolve target or a rendered texture has no inputs and produces black however correct it is — "renders nothing under DRAW_ONLY" is NOT evidence that a draw writes nothing (`catalog.py show 62`) |
| `GEARS_DRAW_PS_CONST_SET=<pshash>:<i>=<x>,<y>,<z>,<w>` | One packed pixel float constant, replaced (`;`-separated for several). Answers "is the picture wrong because of THIS number?" by substituting a working capture's value. **Never a fix** — the number comes from the guest, so a wrong one is a defect on the CPU side. It is what proved catalog #73: forcing c7 and c8 took a wholly black frame to 99.4% non-black, and either one alone left it black |
| `GEARS_DRAW_NOTEX=1` | Texture content (white stubs) |
| `GEARS_DRAW_NOBLEND=1` | The blend equation |
| `GEARS_DRAW_NOSTENCIL=1` | **DIAGNOSTIC control arm**: build every pipeline with the stencil test off, as this backend did before stencil existed. Stencil is not a corner case here -- 15 to 29 of every gameplay frame's ~90 pipelines set `RB_DEPTHCONTROL.stencil_enable`, and with no stencil test each of those passes ran over the whole screen instead of the pixels a shadow pass marked (`catalog.py show 91`). The frame report prints how many pipelines asked for it, WITH the denominator |
| `GEARS_DRAW_SPLIT_DEPTH=0` | **ON BY DEFAULT since it was measured; `=0` restores the old shared image as a control arm.** One host depth+stencil image per `RB_DEPTH_INFO.depth_base`, instead of one shared by the whole frame. This is the right model -- the console addresses depth by an EDRAM base exactly as it addresses colour, and this title uses four in a gameplay frame (0x0 on 788 draws, 0x5a0 on 51, 0x2d0 on 3, 0x400 on 1) -- and sharing one image is the named cause of catalog #91: the shadow-atlas passes overwrite the SCENE's stencil, so the mask pass that tests it rasterises three full-screen draws and invokes no fragment shader, surviving only where neither 422x422 atlas tile reached. **It is OFF pending a paired capture, and the measurements that condemned it are VOID**: the first mask goes to 364,499 shadowed pixels against the console's 143,816 and the second to none, so something else in that pass depends on the sharing. A mechanism that is right in principle and wrong on screen is how a renderer ends up with two bugs that cancel, so it ships behind this knob until the rest is understood. The OFF arm was measured against the build before the split existed and is within its run-to-run spread. **Every one of those numbers predates the discovery that the split never reached the resolves or the clears**: `PreparedDraw::depthTargetBase` defaults to 0 and the resolve decoder never set it, so under this knob every depth resolve read, and every resolve-borne depth clear landed on, the SCENE's depth image whatever base the copy named -- the shadow atlas resolved at 0.0209 against the console's 0.7079. Fixed in the resolve decoder, and VERIFIED on our side: the first mask loop's marking draws now write 252,120 / 52,907 / 43,939 stencil samples and the shading draws that follow consume exactly those counts (they took ZERO before), the shadow atlas's depth resolve goes 0.0209 to 0.5523, and mask #0 goes 0.5968 to 0.8206 against the console's 0.8513 -- no longer worse than the shared arm. **The paired capture has now been run** (ours 873 / theirs 873, gap 0, 16 of 16 passes shared): the shadow atlas depth resolves MATCH the console -- 0.7095 against 0.7082 and 0.8701 against 0.8754 -- where the broken split read 0.0209 and 0.0206, and mask #0 is indistinguishable from the shared arm within this pass's known run-to-run spread. **That last reason is now VOID and the knob's status is UNDECIDED, not justified.** It stayed off because mask #1 resolved a flat 1.0000 under the split 'where the shared arm gives 0.9599'. The SHARED arm produces a flat 1.0000 there too: `scratch/camerapair_ps`, run with no `SPLIT_DEPTH` set anywhere, resolves its second mask to ONE distinct value over all 921,600 pixels. A flatness census of 106 mask resolves across 30 captures finds the second mask flat at 1.0000 in six of them and flat at 0.0000 in three, spanning BOTH arms -- the outcome tracks the game moment, not the depth model. The reason it went unnoticed is that a constant buffer has zero variance, so the retired correlation-based frontier printed `nan` instead of naming the most informative failure. What still stands FOR the split is internal and needs no console: the shared arm's marking draws write ZERO stencil samples where the split writes 252,120 / 52,907 / 43,939, because a zpass REPLACE tests GEQUAL against a scene depth buffer the shadow atlas has overwritten. Settling it needs an A/B of the two arms on the SAME game moment, held by the camera gate -- every comparison so far has been across different moments of a pass whose content varies between them. **That A/B has now been run** (`tools/depth_arm_ab_run.py`): one frozen camera replayed through four arms -- shared, split, shared again, and the variable UNSET -- all scored against the same console frame. Two findings survive the camera-residual spread that swamps everything else. The shadow atlas depth resolve is **0.3395/0.3441 shared against 0.9983/0.9989 split**, unchanged across residuals from 0.00 to 0.72 thresholds, so the model decides it and not the viewpoint. Against that, the first shadow mask appeared to regress, 0.9484/0.9642 shared to 0.8021/0.8059 split -- **which is now explained and gone**. It was the half-scale depth buffer (`kSysFlag_DepthFloat24` set while the viewport used the full range) becoming visible once the split removed the atlas corruption that had been partly compensating for it: two defects were cancelling, and the split was correct even while making that number worse. With the scale fixed, mask #0 scores 0.9899 on the split arm and shadows 11.35% against the console's 11.39%, and mask #1 went from a flat 1.0 to 33 distinct values at 4.85% against the console's 33 and 4.88%. Nine-of-ten claims from an earlier reading of this A/B were withdrawn: that run's control arm happened to match the camera at 0.00 thresholds while the others matched at 0.59 and 0.72, and the resulting 'noise floor' was measuring viewpoint, not run-to-run variation. The default flipped because the split is the correct memory model and it fixes a 0.34-to-0.999 pass, not because it wins everywhere |

## Retired

| Knob | What happened |
|---|---|
| `GEARS_SHADER_ARGSCAN=1` | **Gone.** The exhaustive 51-entry D3D argument scan identified `sub_82222808` as `SetPixelShader` and `sub_82222B98` as `SetVertexShader`; those exact bindings now live in the Gears 1 adapter and are checked through `GEARS_NATIVE_RHI_OBSERVE`. Keeping dozens of resolved wrappers in the shipping hot path only added branches. The historical method and result remain in catalog #21. |
| `GEARS_DRAW_RT=1` | **Gone.** The resolve→texture link is ON by default; `GEARS_DRAW_NORT=1` disables it. The old name lingered in scripts and evidence lines long after the code stopped reading it, so runs were passing a variable that did nothing — which is exactly what this registry exists to prevent |
| `GEARS_DRAW_FRAME=1` | **Gone.** Whole-frame rendering is what the runtime does; there is no arm in which the guest's draws are executed and none of them are shown. `GEARS_DRAW_FRAME_AT`/`_COUNT` still bound which frames |
| `GEARS_DRAW=1` | **Gone** with the one-shot hot-pair renderer it fired. That path built its own pipeline for one known vertex/pixel pair; the whole-frame renderer issues the same draw as one of the frame's draws, through the code that actually ships. Two renderers meant the milestone one drifting untested |
