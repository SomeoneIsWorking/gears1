# Codemap

This map owns placement and responsibility only. Capability state is in
`docs/project-state.md`; evidence order is in `docs/re-frontier.md`.

| Owner | Current location | Responsibility | Boundary |
|---|---|---|---|
| Product launcher | `run.sh`, `bootstrap.py`, `tools/gearsue3_bootstrap/` | Resolve locked Python and the user's disc, authenticate its `default.xex`, refuse missing native dependencies by name, build `build/product/gears1`, and replace itself with the product. | Owns no runtime behaviour; `--prepare` stops before launch. Maintainer runs use `tools/run_offscreen.py`, never `run.sh`. |
| Gears 1 product | `runtime/product/` | Parse the product command line, compose the title's `x360port::SystemSessionConfig` (input readers, native overrides, audio and host-input policy), and run it windowed or offscreen; an offscreen run may serve the loopback control channel (`control_channel.*`, guest-memory request parsing in `memory_request.*`, client `tools/product_control.py`; `tools/combat_route.py` plays Act 1 from the first firefight to the next saved checkpoint through it with the closed-loop steps of `tools/route_driver.py` over the world model and steering geometry of `tools/combat_world.py`, walking the level's navigation graph with `tools/navigation.py` and reading the save with `tools/gears1_checkpoint.py`; `run_stop.h` lets `POST /api/stop` end the run early). | Kernel, file-system, GPU, audio, and input services are the session's; title policy is only what `gears1_session.*` supplies. |
| Headless product runs | `tools/run_offscreen.py` | Provision as `run.sh` does, then run the product offscreen and silent under `scratch/offscreen/` with a profile navigation walk, per-interval captures, and a contact sheet. | Observes; never a gate. Uses an isolated storage root, not the player's saves. |
| Consumed Git dependency contract | `tools/gearsue3_bootstrap/dependency_checkout.py`, `tools/require_git_checkout.py`, `tests/test_dependency_checkout.py` | Require an immutable revision, a clean worktree, and any caller-declared source marker before CMake consumes a shared checkout. | CMake invokes the locked Python owner; it does not reimplement Git cleanliness or revision policy. |
| Exact title identity | `config/titles/gears1.toml`, `tools/title_identity.py`, `runtime/title_profile.*` | Validate exact container/image hashes and title policy. | No CPU translation, generated source, or runtime cache ownership. |
| Gears 1 image adapter | `runtime/gears1_guest_image.*` | Authenticate the profile's loaded image and adapt the shared PE layout into one flat `x360port::GuestModule`. | Does not decrypt/inspect XEX containers or own shared PE parsing, import services, or gameplay policy. |
| Gears 1 XAM video import | `runtime/titles/gears1/xam_video_services.*` | Claim the `XGetAVPack` export by name and answer it with the title's configured AV-pack result through the checked import context. | Unbound XAM services must refuse through the shared import-exit contract; this owner does not own input or generic XAM policy. |
| Gears 1 runtime composition | `runtime/gears1_runtime.*` | Own the authenticated image-to-x360port composition, persistent variable-import storage, the resolved claim table each host service contributes its named exports to, and the fail-closed unsupported-service route. | Does not implement ungrounded title services, gameplay, or the product launcher. |
| Gears 1 native audio mix | `runtime/titles/gears1/audio_mix.*` | Bind exact address `0x825F2D40` through x360port and mix validated guest vectors in the title-owned native operation, reproducing the guest's fused multiply-add and return value; `audio_mix_differential.*` checks it against the original body on live calls for `--verify-audio-mix`. | Must not use generated PPC state or raw guest pointers; owns no dispatch policy beyond its own address. |
| Guest image layout for RE tooling | `tools/guest_image.py` | Load the image as the XEX loader leaves it (sections at their raw offsets) for address-based tools and refuse a copy re-laid by section VirtualAddress by name. | Does not decode XEX containers or own PE layout; `x360port`'s inspector writes the loaded image. |
| Gears controller source and XAM adapter | `runtime/input.*`, `runtime/titles/gears1/xam_input_provider.*`, `runtime/titles/gears1/desktop_controls.*` | Arbitrate the window's keyboard and mouse (mapped to the pad by the title's PC bindings), script, and remote input under one coherent pad snapshot; map the single local Gears user and virtual-pad capability policy to the shared XAM reader contracts. | Shared `x360port` binds ordinals 400/401 and owns the guest ABI and bounded big-endian writes; the title never writes guest memory directly. |
| Shared Xbox 360 execution | `../../shared/x360port` at the revision pinned in `CMakeLists.txt`, consuming `extern/xenia/` | Xenia `Memory`, `Processor`, `ThreadState`, `RawModule`, x64/A64 backend selection, authenticated image mapping, typed imports with fail-closed service refusal, guest calls, image-scoped native override/original-call entry dispatch, title-neutral device-memory callbacks, automatic/title-reported executable-write invalidation including active-call exits, bounded nested guest execution, and reason-labelled fallback accounting. | No Gears address, hash, renderer policy, or UE3 behavior; Xenia owns fallback semantics and title-specific cache-control remains a title contract. |
| Shared UE3/Xbox contracts | `../../shared/x360ue3` at the revision pinned in `CMakeLists.txt` | Independently authored UE3-on-Xbox binding-schema, frame-lifetime, and semantic-RHI contracts consumed by Gears. | No Gears addresses, exact identity, XEX loading, guest execution, or native backend policy; never copies or depends on `../../shared/ue3`. |
| Native engine: cooked packages | `runtime/engine/package/`, `tools/package_census/`, `tests/test_engine_package.cpp` | Decode Gears 1 cooked packages from disc bytes (LZO1X, compressed records, summary, name/import/export tables), resolve object paths and export data, and load a content directory's packages by name (`ContentFiles`, `PackageStore`). `gears_package_census` loads and decodes every package of an extracted disc. | Independently written; never executes guest code or reads guest memory. Property and asset layers build on `Package`. |
| Native engine: objects | `runtime/engine/object/`, `tools/package_inspect/`, `tests/test_engine_object.cpp` | Serialized object prelude, tagged property streams (including structs saved field by field and arrays of them), class ancestry from script packages, class default objects and their default subobjects inherited through the superclass chain (`ClassDefaults`), typed property lookup, import resolution (found, null, or cooked out), and bulk data (inline, LZO, separate file). | Knows no asset layout; asset layers read `NativeData()`. |
| Native engine: assets | `runtime/engine/texture/`, `runtime/engine/mesh/`, `tools/texture_export/` | Texture2D mips untiled from the Xenos 2D layout; StaticMesh LOD sections, vertices, and indices. | CPU-side decoded data only; GPU upload belongs to the renderer. |
| Native engine: BSP | `runtime/engine/bsp/`, `tests/test_engine_bsp.cpp` | Model vectors, points, nodes, surfaces, and vertex pool; ModelComponent elements with their 2D light maps; `ComponentGeometry` triangulates a component into a mesh LOD with one section per material (texture coordinate set 1 in its light map), reading each shared model once. | CPU-side geometry in world space. |
| Native engine: materials | `runtime/engine/material/` | `MaterialSurfaces`: a material's base-colour texture, blend mode, two-sidedness, lighting model, and the texture channel its opacity reads, from the base material's cooked expression graph with material-instance texture parameters. | Reads the authored graph; does not evaluate or compile material expressions. |
| Native engine: scene | `runtime/engine/scene/`, `tests/test_engine_scene.cpp` | `World` (a persistent level and every sublevel its WorldInfo streams, with the first PlayerStart), per-level placement of actor-owned static mesh components and model components (`LevelScene`), shared placement-property reads, the decoded static-mesh cache (`StaticMeshes`) that rendering and collision share, row-vector transforms in the title's Z-up frame, and the camera's Vulkan clip-space mapping. | No GPU objects and no simulation. |
| Native engine: game | `runtime/engine/game/`, `tests/test_engine_game.cpp` | The running game: `CollisionWorld` (BSP and collision-flagged static mesh triangles on a uniform grid, swept-sphere queries), `WalkingMovement` (capsule walking, falling, sliding, step-up, floor following), `PlayerPawn` (control rotation and facing), the over-the-shoulder `PlayerView`, and `GameWorld`, which spawns the player at the PlayerStart and simulates in fixed ticks. `pawn_defaults` names the Gears 1 game type, reads the pawn class it spawns, and builds `PawnTuning` from that class's defaults. `PlayerInput` is the device-neutral intent it consumes. | No devices, windows or GPU; takes decoded scene data and class defaults. |
| Native engine: renderer | `runtime/engine/render/`, `tools/level_render/` | Headless Vulkan device, offscreen target and readback, GPU static meshes and textures (sRGB or linear), per-frame constants (`FrameConstants`), texture descriptors for colour, opacity, and three light-map coefficients, `DrawMaterials` (a section's material and light map to its textures, blend, alpha test, and lighting), one mesh pipeline per blend, and `LevelRenderer`, which prepares and draws a level's sections; swapchain presentation (`Swapchain`, `WindowFrames`, which letterboxes the rendered frame into the window); `gears_level_render` draws a level package and every sublevel it streams to one image. Optional: built only with the Vulkan loader and glslc. | Separate from the Xenia-hosted presenter under `runtime/`; takes decoded assets from the scene and asset layers. |
| Native engine: app | `runtime/engine/app/` | `gears_native`, the game executable: the SDL3 window and Vulkan surface (`GameWindow`), keyboard, mouse and gamepad translated into `PlayerInput` (`DeviceInput`), and the loop that advances `GameWorld` and draws its view. Built when SDL3 is found. | Composes the other engine layers; owns no game rules. |
| Gears-family native host | `runtime/` | Input, audio, kernel/device services, renderer, diagnostics, frame ownership, and executor-independent guest-memory views. | CPU execution enters only through `x360port`. |
| XMA frame decoder dependency | `extern/ffmpeg-xmaframes/`, `cmake/ffmpeg_xma.cmake` | Build and expose the maintained per-frame XMA decoder for native audio owners. | Decoding stays in the dependency; title scheduling, guest buffers, and audio policy stay in `runtime/`. |
| Gears 1 adapter | `runtime/titles/gears1/`, `config/titles/gears1.toml` | Exact addresses, ABIs, native operations, renderer bindings, revision policy, and maintainer probes of title state through `x360port::SystemSession::ReadGuestMemory` (`guest_chain.*` follows the engine's pointers to the local controller, `player_probe.*` reads the player and the world's pawns, `navigation_probe.*` the level's navigation graph). | Other titles get separate adapters; shared owners contain no Gears 1 constants. |
| Native renderer | `runtime/gpu_*`, `runtime/native_*`, `runtime/rhi_*`, `runtime/titles/gears1/native_pass.*` | Xenos state/materialization, host Vulkan resources, semantic frame plans, and independently authored native passes. | Existing source is buildable evidence, not a live gameplay claim until fed by Xenia. |
| Xenos shader tools | `xenia_gpu/`, `tools/xenos_translate/`, `tools/system_constants/` | Offline inspection of user-supplied shader captures and register snapshots using Xenia's GPU libraries. | Measurement only; never a CPU executor or player prerequisite. Diagnostics use Lucent logging. |
| Native frame replay | `tools/frame_replay/` | Compose executor-independent native renderer owners over a user-supplied captured frame. | Diagnostic only; does not execute guest CPU code or prove live gameplay. |
| Ghidra analysis scripts | `tools/ghidra_scripts/` | Maintainer-only binary inspection through the shared Ghidra RE workflow. | Never required, fetched, or invoked by the player product. |
| Oracle | `tools/xenia_oracle/`, `tools/oracle_compare.py`, `tools/frame_parity.py` | Independent reference-emulator observations and bounded differential evidence. | Oracle output is evidence, not a runtime fallback or shipping dependency. |
| Migration boundary gate | `tools/check_migration_boundary.py` | Scan tracked and untracked first-party source, tool, config, and documentation paths for retired CPU-product surfaces, forbidden direct process/diagnostic access, and extra shell entry points. | Build/dependency/scratch trees are excluded; the game-authored phrase “command-list interpreter” remains valid. |
| Distribution gate | `tools/check_distribution_clean.py` | Refuse copyrighted inputs, executable/archive payloads, private-source dependencies, and unverifiable generated artifacts. | Does not replace runtime identity validation or the migration-boundary gate. |
| Architecture/quality gates | `tools/check_source_structure.py`, `tools/check_cpp_quality.py` | Source-size ratchet, format, and lint checks against the real compile database. | Maintainer verification selects Clang; the project does not reject supported user compilers. |
| Boundary-target compiler warnings | `CMakeLists.txt` calling the pinned `x360port_enable_warnings` CMake owner | Apply driver-appropriate diagnostic groups and warnings-as-errors to the Gears discriminator. | The shared framework owns GNU-style, clang-cl, and MSVC flag selection; Gears does not duplicate it. |
| Import-service inventory | `tools/import_inventory.py`, `tools/gearsue3_imports/` | Join the image's import manifest to Xenia's ordinal tables and the recovered handler corpus, so the migration work list is the set of exports the title reaches; refuse a missing manifest, a moved ordinal table, a table that parses to nothing, a runtime tree with no sources, and a host-service tree that claims no export. It reports recovered-handler coverage and bound services separately, because a service implemented in `x360port` is bound while carrying no recovered handler. | Reads claimed export names from the composed service sources, not from a running binding table, so a claim the title does not compose would still count. |
| Gears/x360port discriminators | `tests/test_gears1_dynarec_boundary.cpp`, `tests/test_gears1_real_leaf.cpp`, `tests/test_remote_input.cpp`, `tests/test_gears1_desktop_controls.cpp` | Exercise synthetic native/JIT wiring and, with the ignored user XEX, the real leaf, import refusal, and controller-state thunk over the retained input owner. | Synthetic coverage is not title conformance; the real-image test is a headless import/leaf discriminator, not gameplay. |
| Boundary verifier and hosted matrix | `tools/verify_dynarec_boundary.py`, `.github/workflows/dynarec-boundary.yml` | Configure the exact x360port/Xenia revisions with Clang/Ninja and execute the Gears discriminator on each implemented native host boundary. A test that ends on a signal has its threads' stacks printed: rerun under gdb on Linux, from its ReportCrash report on macOS (`tools/gearsue3_bootstrap/crash_triage.py`). | No game input; Android is added only with a real APK/runtime owner. |

`run.sh` is the only shell file. All other project automation is Python.
